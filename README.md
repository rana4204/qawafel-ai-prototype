# Qawafel SME Financing Prototype

Qawafel is a Python and Streamlit prototype for exploring an SME financing request workflow. It accepts sample business records, extracts and validates financial data, reconciles invoice payments, and presents a structured financial assessment. A local Mock Bank API simulates application receipt and status updates; it does not connect to a real bank.

## Features and workflow

1. A customer starts a financing request in the Client Portal and enters request and repayment details.
2. The customer provides a sales invoice workbook and a bank statement PDF. A supporting PDF is optional. The portal uses a clearly marked synthetic company profile for its demo company context.
3. Qawafel extracts the invoice rows and bank transactions, validates the data, matches invoice collections to transactions, and calculates financial summaries and rule-based insights.
4. Once analysis is current and required validation passes, the client can submit. Qawafel sends the application and a structured package to the in-process Mock Bank API and receives a simulated acknowledgment and bank reference.
5. The Client Portal shows the latest known status and timestamped history. Status events can be generated through the Mock Bank API module and are read when the customer opens application details.

The prototype has no Bank Portal or bank employee interface.

## Technology

- Python 3.10 or newer (verified locally with Python 3.12.3)
- Streamlit for the Client Portal
- pandas and openpyxl for workbook processing and analysis
- pdfplumber for reading selectable text in PDFs
- ReportLab for generating the synthetic statement PDFs
- Plotly for charts

`openai` and `python-dotenv` are listed in `requirements.txt`, but the current app does not call an OpenAI API and does not require an API key. The financial insights in this prototype are generated by deterministic Python rules; they are not a lending decision.

## Windows setup

Install Python 3.10 or newer and open PowerShell in the project directory. The following commands use Python 3.12; change the launcher version if needed.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

If PowerShell blocks virtual-environment activation, use the current-process policy for this terminal, then activate:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Run the application from the project root:

```powershell
streamlit run app.py
```

No `.env` file or bank credentials are needed for the current prototype. Do not place secrets in source files or sample data.

## Synthetic sample datasets

Each folder contains `company_profile.json`, `invoices.xlsx`, and `bank_statement.pdf`. The workbook keeps `Invoices` as its first sheet for the application loader and includes an `About This Data` sheet with a synthetic-data notice. Each PDF is visibly marked as synthetic test data and not a real bank statement. Names and registration identifiers are fictional placeholders.

- `sample_01_healthy`: complete, consistent invoice and transaction records.
- `sample_02_data_issues`: intentional missing and duplicate invoice data and inconsistent records.
- `sample_03_cashflow`: overdue invoices that demonstrate collection and cash-flow pressure.
- `sample_04_growth`: increasing monthly invoice revenue.
- `sample_05_complex`: partial payments and transaction matching edge cases.

Regenerate all five fixtures from the project root with:

```powershell
python -m modules.generate_sample_data
```

Validate the generated samples with:

```powershell
python -m modules.validate_sample_data
```

## Processing and assessment

- **Extraction:** `document_extractor.py` reads invoice workbooks with pandas/openpyxl and extracts transaction tables from selectable-text bank statement PDFs with pdfplumber. It can also extract text from an optional supporting PDF. Scanned PDFs may need OCR, which is not implemented.
- **Validation:** `data_validator.py` checks required fields, missing or malformed values, duplicate invoices, and transaction data quality. Validation errors block submission in the Client Portal.
- **Reconciliation:** `invoice_matcher.py` compares invoice records with transaction descriptions and amounts to identify confirmed, unmatched, or ambiguous matches.
- **Financial analysis:** `financial_analyzer.py` calculates summaries from the supplied invoice and transaction data. `ai_insights.py` applies explicit rules to report findings and data limitations. Results depend on the quality of the uploaded data and are not a credit decision or affordability guarantee.

## Mock Bank API simulation

`modules/mock_bank_api.py` is an in-process Python module, not a network service. The Client Portal submits the Qawafel application reference and structured financing package to `MockBankAPI.submit_application()`. The mock stores the request in memory and returns an acknowledgment, a generated bank reference, a `received` status, and a timestamp. Identical submissions are idempotent within the same API instance.

Status updates are simulated by calling `MockBankAPI.generate_status_update(application_reference, status, note=...)`. The Client Portal reads the current status and stored events when application details are opened. There is no webhook, external bank endpoint, polling service, employee UI, authentication, or real bank connection. The API store is held in Streamlit session state for the current session; it is not durable and is lost when that session ends.

## Tests and compilation

Run the full test suite from the project root:

```powershell
python -m unittest discover -s modules -p "test*.py"
```

Run only the Mock Bank API and client submission tests:

```powershell
python -m unittest modules.test_mock_bank_api modules.test_client_submission
```

Compile the app and modules:

```powershell
python -m compileall -q app.py modules
```

## AI tools used during development

OpenAI Codex was used as an AI-assisted development tool for code review, implementation support, and documentation. The running prototype does not use a generative AI service; its financial insight engine is rule-based.

## Prototype limitations

This project is for demonstration and testing. It has no user authentication or authorization, durable database, real bank integration, bank employee workflow, OCR for scanned documents, production security controls, or lending decision engine. Uploaded documents and application records are handled locally by the prototype workflow; sample data must remain synthetic.
